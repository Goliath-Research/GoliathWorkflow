3  Project Config and Layout

3.1 Purpose

Define a project JSON that can run through stability, freeze, model, and evaluation without per-stage schema drift.

3.2 Repository vs /work (what goes where)

Repository (versioned, documented) /work/<disease>/ (study-specific)
Pipeline profiles (workflow_engine/domain/profiles/) project_*.json — cohorts, comparisons, sample paths, output_base, study step_config
DomainPrograms (*.program.json under workflow_engine/domain/) Sample list CSVs under data/
JSON schemas (schemas/config/) Run outputs (monte_carlo_runs/, stability/, …)
User manual, theory, docs/domain_program_language.md
  • Point methyl-workflow-run --program at a repo DomainProgram path.
  • Point --context / projectPath at a project JSON on /work.
  • Optional --context-file loads a profile from workflow_engine/domain/profiles/.
  • Do not treat repo workflow_engine/domain/checks/*/configs/project_*.json as production configs (CI smoke only).
  • Do not copy *.program.json into /work/<disease>/configs/.

3.3 Minimum structure

Use one project file containing:

  • global cohort metadata (controls, diseases, comparisons),
  • filesystem anchors (output_base, samples_base_path),
  • step-specific overrides under step_config.

Core stage driver:

  • step_config.validation (parsed into MonteCarloConfig by methyl-validation).

Upstream sample prep (before stability) uses:

  • step_config.alignment_qc — guardrails, cycle screening, optional cfDNA fragmentomics (Chapter 3).
  • step_config.extraction_qc — post-extract coverage and conversion thresholds (Chapter 3).

3.4 Validation stage keys that matter most

  • split policy: train_fraction, n_iterations, seed
  • stability controls:
    • run_stability
    • stability_dmp_freq
    • stability_min_balanced_accuracy
    • stability_gene_freq
    • stability_featurecuts_enabled
    • stability_target_balanced_accuracy
    • stability_min_selected_dmps
  • freeze/model paths:
    • freeze_stable_dmp_csv (optional)
    • production_output_dir (optional)
  • backend/model:
    • model_backend
    • feature_mode
    • ecdf_second_stage_enabled
    • backend-specific tabular_* / generative_* keys

3.5 Output layout

Most runs write to:

<output_base>/<project_name>/monte_carlo_runs/

Important subtrees:

  • run_XXXX/ (per-iteration artifacts)
  • stability/ (stable panel and summaries)
  • production/ (freeze and final model outputs)
  • model_mc/ (backend comparison runs)
  • post_model_validation/ (frozen-model descriptive evaluation)

3.7 Do not do this

  • Do not put blind-only predictor config (predictor.blind) into validation-driven runs.
  • Do not change samples_base_path between stages without explicit remap.
  • Do not run --freeze before stable panel exists.

3.8 Success checks

  • Project loads in methyl-validation --project ....
  • step_config.validation exists and parses.
  • Run directories appear under expected root.
