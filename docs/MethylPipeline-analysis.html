MethylPipeline Comprehensive Analysis

Theory, architecture, implementation, and usage

Author

MethylPipeline Team

Published

May 29, 2026

1 Executive Summary

MethylPipeline is a monorepo for DNA methylation analysis that combines:

  1. empirical distribution modeling (ECDF/histogram centroids),
  2. differential methylation discovery with FDR control,
  3. stability-based feature selection via Monte Carlo,
  4. genomic interpretation (mapping + enrichment + progression synthesis), and
  5. model training/selection workflows.

The scientific spine is:

  • methyl-validation (orchestration) -> methyl-centroid -> methyl-detector -> methyl-mapper -> methyl-enricher -> methyl-disease-progression.

Supporting packages (methylclassifier, methylpredictor, methylalignmentqc, methylcluster) integrate around this core.

3 Theory

3.1 Data representation: methylation values and centroid summaries

At locus \(i\) for sample \(s\):

\[ x_{si} = \frac{m_{si}}{m_{si} + u_{si}}, \]

where \(m\) and \(u\) are methylated/unmethylated counts.

Cohort sufficient statistics used throughout the pipeline:

\[ \hat\mu_i = \frac{S_{x,i}}{N_i}, \qquad \hat\sigma_i^2 = \max\!\left( \frac{S_{x^2,i} - S_{x,i}^2/N_i}{\max(N_i-1,1)}, \varepsilon \right). \]

methylcentroid stores these plus binned histograms per locus/context/chromosome, enabling downstream distribution comparison without reloading raw read-level data.

3.2 ECDF reconstruction and nonparametric two-sample screening

The ECDF at bin edges is reconstructed from centroid histograms and interpolated (PCHIP-style) in methylutils.

Core screening includes:

  • Kolmogorov-Smirnov style distance on reconstructed ECDFs,
  • Mann-Whitney U approximation from bin counts,
  • Storey q-values for multiple testing control.

Storey components (implemented in storey_qvalues):

\[ \hat\pi_0(\lambda) = \frac{\#\{p_j > \lambda\}}{(1-\lambda)m}, \qquad q_{(i)} = \min_{j \ge i} \frac{\hat\pi_0\, m\, p_{(j)}}{j}. \]

3.3 Canonical biological effect size

MethylPipeline separates statistical significance from biological ranking. The canonical effect-size formulation in effect_size_from_components is:

\[ \mathrm{effect\_size}_i = |\Delta\mu_i|\,(1-\mathrm{overlap}_i)\, \exp\!\left(-\lambda_{\mathrm{var}}(\sqrt{\sigma_{1i}^2}+\sqrt{\sigma_{2i}^2})\right), \]

optionally multiplied by a mean-level weighting factor.

This is a prioritization score, not a p-value.

3.4 Stability selection (Monte Carlo)

With repeated train/validation splits, recurrence of each discovered DMP is:

\[ \hat f(d) = \frac{1}{R^*}\sum_{r=1}^{R^*}\mathbf{1}[d \in \mathcal{D}_r]. \]

Stable panel construction in stability.py ranks by:

\[ \mathrm{combined\_score}(d) = \mathrm{effect\_size}(d)\sqrt{\hat f(d)}, \]

followed by thresholding and optional elbow trimming.

3.5 Gene-level importance theory

In mapper aggregation, the canonical gene importance is tied to effect consistency and support:

\[ \mathrm{gene\_effect\_compound} = \mathrm{gene\_effect\_abs\_wmean} \times \mathrm{gene\_direction\_coherence} \times \sqrt{\mathrm{gene\_support\_freq}}. \]

gene_importance is canonicalized to this compound metric in current implementation.

3.6 Disease progression synthesis theory

methyldiseaseprogression is intentionally deterministic and file-driven:

  • input: per-stage mapper and enricher outputs,
  • output: ranked long tables and heuristic stage labels (e.g., early_only, late_only, monotonic_up, stable_across_stages).

This is evidence synthesis over staged contrasts, not a latent-time probabilistic model.

3.7 Method taxonomy and caveats

  • Principled/statistical: FDR control, centroid sufficient statistics, asymptotic tests.
  • Approximate: histogram-derived MWU and ECDF grid approximations.
  • Heuristic: effect-size weighting, stability cutoffs, progression labels.
  • External dependencies: Enrichr services, optional STRING/PPI data.

4 Architecture

4.1 Package architecture

The monorepo package graph centers on shared methylutils and orchestration via methylvalidation.

4.2 End-to-end data flow

The data flow from samples to model/paper outputs is phase-based.

4.3 Core phase orchestration

methyl-validation in pipeline_runner.py orchestrates:

  • Monte Carlo iterations (centroid -> detector only),
  • stability aggregation (--stability),
  • production freeze (--freeze):
    • fixed DMP panel injection,
    • production centroid/detector/mapper/enricher/progression pipeline,
  • model training/evaluation (--model, --model-mc, --post-model-validation).

4.4 Canonical data contracts

Key contracts between stages:

  • detector exports DMP panels (dmps-*.csv),
  • mapper exports per-comparison all-gene_name-combined.csv,
  • enricher consumes mapper combined CSV and emits enrichment_merged.csv and module tables,
  • progression consumes mapper+enricher stage outputs,
  • model bundle uses detector DMP index plus optional mapper annotation cache.

5 Implementation

5.1 Mapper implementation highlights

In bedtools_mapper.py:

  • explicit detailed-to-parent feature roll-up map (_DETAILED_TO_PARENT),
  • normalization path (_normalize_feature_type) preserving explicit features when configured,
  • exclusive (gene, DMP) hit assignment for feature-level counting,
  • combined p/q and weighted effect metrics,
  • canonical gene_importance assignment from gene_effect_compound,
  • curated output column pruning in _prune_gene_output_columns.

5.2 Validation configuration and model-bundle implementation

In methyl_validation/config.py:

  • strict Pydantic models for MC + backend profiles,
  • DEFAULT_MAPPER_GENE_COLUMNS and configurable mapper_gene_columns.

In methyl_validation/model_bundle.py:

  • build_mapper_annotation_cache composes per-locus mapper annotation rows,
  • optional join of configured per-gene mapper columns,
  • HDF5 writing/reading in bundle schema v2 with core and passthrough columns.

5.3 Enricher strict-contract behavior

methyl_enricher/enricher.py enforces mapper contract fields and canonical score usage:

  • required columns include gene_name, gene_importance, mean_effect_size, unique_dmps,
  • strict filter checks fail with explicit ValueError when required columns are absent.

Compatibility bridge implemented for legacy filter knob:

  • if min_dmp_count requested and dmp_count missing,
  • fallback applies threshold to unique_dmps with warning.

5.4 Progression robustness behavior

progression.py and gene_set_coverage.py now support per-stage graceful degradation:

  • malformed/missing stage inputs are logged and skipped in stage loops,
  • global pipeline can continue in non-strict mode,
  • strict mode still fails fast when required by caller.

5.5 GPU and fallback implementation

methyl_utils/gpu_detection.py centralizes GPU capability checks and state.

methyl_utils/statistical_tests.py includes guarded GPU execution with CPU fallback in critical statistics paths (e.g., Storey q-values and Beta MOM estimation) so transient CUDA runtime issues do not crash full runs.

6 Usage

6.1 Environment and installation

Preferred host setup from repo root:

cd /home/ubuntu/MethylPipeline
bash scripts/setup_host.sh --system-deps --gpu
source .venv/bin/activate

For explicit GPU profile alignment:

source .venv/bin/activate
pip install -r requirements-gpu-cuda12.txt \
  -c scripts/constraints-cuda12.txt \
  --extra-index-url https://pypi.nvidia.com

6.2 Project JSON configuration model

Core structure:

  • top-level project metadata (project_name, output_base, samples_base_path, chromosome/context scope),
  • cohort hierarchy (controls, diseases, stage groups),
  • comparison strategy (control_vs_each_disease, all_pairs, or explicit list),
  • step_config blocks:
    • centroid, detection, mapper, enricher, progression, validation, optional others.

Reference docs:

  • docs/theory/chapters/11-project-configuration.qmd
  • docs/theory/chapters/13-configuration-reference.qmd

6.3 Staged operational workflow

Typical commands:

# 1) Stability
methyl-validation --project /work/prostate-cancer/configs/project_Healthy_vs_PCa1-4-CG.json --stability

# 2) Freeze
methyl-validation --project /work/prostate-cancer/configs/project_Healthy_vs_PCa1-4-CG.json --freeze

# 3) Model
methyl-validation --project /work/prostate-cancer/configs/project_Healthy_vs_PCa1-4-CG.json --model

Important behavior:

  • --skip-detection is supported in --stability and --freeze,
  • --skip-detection implies --skip-centroid.

8 Limitations and operational caveats

  1. Monte Carlo stability improves internal robustness, but external cohort validation remains necessary.
  2. Some inferential components are approximations by design (histogram-derived tests, ECDF interpolation grids).
  3. Mapper/enricher/progression stages include heuristic ranking and synthesis layers in addition to strict statistical tests.
  4. Third-party services (e.g., Enrichr, optional network APIs) can affect reproducibility and runtime behavior.
  5. GPU acceleration should be treated as a performance path with fallback safety, not a substitute for explicit environment validation.
